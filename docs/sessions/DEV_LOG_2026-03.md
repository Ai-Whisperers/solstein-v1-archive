### Findings

1. The master audit markdown is no longer a reliable execution truth source by itself.
   Many entries remain marked `Open` after code moved on. Fix work must continue from code-plus-tests, not status columns alone.

2. The nearest unit tests around these connectors are weak and in some cases stale.

3. The project already has broad pytest, ruff, mypy, and Make targets, but the enforcement is not strict enough to prevent semantic drift.
   The main gap is not only missing tests. It is also missing boundary-contract tests, schema gates, API contract verification, and CI segmentation that blocks high-risk merges early.

   Root `tests/conftest.py` forced collection-time import of the full app graph, which pulled in runtime configuration and unrelated startup dependencies. Narrow regression tests should not need API boot just to be collected.

5. The schema system is fragmented across domain models, API schemas, source models, evidence models, and ORM models.
   The main technical debt is not absence of types. It is the lack of enforced validation exactly where one schema family hands off to another.
