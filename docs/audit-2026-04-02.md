## ADDENDUM: Pipeline Field Loss — Root Cause Confirmed (2026-04-02)

> Added after systematic code trace of the full pipeline transformation chain.
> Backlog: `EPIC-086` (STORY-348–351), inserted at top of `planning/QUEUE.md` as P0 emergency.

### The Core Problem

Every score, classification, and report produced by this system is derived from a pipeline that
**silently discards the majority of the data it collects**. This is the structural reason outputs
appear fabricated or thin — the data exists in the adapters but never reaches the scoring engine.

### Four Confirmed Loss Layers

#### Layer 1 — `src/solstein/research/aggregate.py`
Per-source-type extractors (`_extract_yahoo_finance`, `_extract_crunchbase`, etc.) map only
hardcoded field lists. Any field the adapter returns that isn't in the extractor's list is dropped here.
This layer is incomplete but not the primary culprit.

#### Layer 2 — `src/solstein/research/signals.py` (LARGEST DROP)
Only **10 signal extractors** are defined in `_SIGNAL_EXTRACTORS`. The aggregator correctly produces
14 fact types that have **no signal extractor AND no Company mapping**:

| Orphaned Fact Type | Source |
|--------------------|--------|
| `ebitda` | YahooFinance |
| `net_income` | YahooFinance |
| `pe_ratio` | YahooFinance |
| `current_price` | YahooFinance |
| `eps_ttm` | YahooFinance |
| `exchange` | YahooFinance |
| `sector` | YahooFinance |
| `products` | Website adapter |
| `pricing_model` | Website adapter |
| `target_customers` | Website adapter |
| `positive_article_count` | News adapter |
| `negative_article_count` | News adapter |
| `patent_categories` | Patents adapter |
| `last_round_amount` | Crunchbase |

Additionally 5 fact types have signal extractors but are not mapped to Company fields (Layer 3 gap): `last_round_stage`, `funding_rounds`, `employee_growth_pct`, `ai_related_positions`, `ai_signal_strength`.

Facts already wired via direct `company_builder.py` fact lookups (likely OK — verify during STORY-348): `name`, `website`, `description`, `headquarters`, `founded_year`, `tech_stack`, `investors`.

#### Layer 3 — `src/solstein/research/company_builder.py`
`build_company_entity_from_signals()` only maps a subset of surviving signals and facts into the
`Company` constructor. `FinancialMetric.ebitda_margin` (a ratio) and `recurring_revenue_pct` are never
populated. The raw `ebitda` absolute value also needs a dedicated field — it cannot be stored in
`ebitda_margin` without first computing the ratio.

#### Layer 4 — `src/solstein/domain/models.py` — `extra="ignore"` (MAKES ALL LOSSES INVISIBLE)
Both `Company` and `FinancialMetric` use:
```python
model_config = ConfigDict(extra="ignore")
```
This was set deliberately in STORY-251. The documented intent was to prevent unknown keys from leaking
into `model_dump()` output. The actual effect is that every mapping error in Layers 1–3 produces
**zero observable signal** — no exception, no log line, no test failure. The domain model becomes
a silent corruption sink that makes structural bugs undetectable.

### Why This Causes Hallucinated Output

When 70%+ of collected data is silently discarded:
- The scoring engine runs on mostly-None fields → scores are extrapolated from minimal signal
- Classification (Phoenix/Salt/Lead) is assigned based on absent data → labels are not trustworthy
- Report narratives are generated from thin/absent facts → LLM fills gaps with fabricated content
- Every new adapter field added will suffer the same loss until the gate is in place

### The Fix (EPIC-086, STORY-348–351)

1. **STORY-348**: Change `extra="ignore"` → `extra="forbid"` on `Company` and `FinancialMetric`.
   Makes all existing losses immediately visible as `ValidationError`.

2. **STORY-349**: Add signal extractors for all 16+ orphaned fact types in `signals.py`.

3. **STORY-350**: Add the missing fields to `Company` and `FinancialMetric`, wire all signals
   and facts through `company_builder.py`.

4. **STORY-351**: Add a permanent CI regression gate that asserts field survival across all
   pipeline layers — prevents this class of bug from re-appearing silently.

### Key Files

| File | Role in the loss |
|------|-----------------|
| `src/solstein/research/aggregate.py` | Layer 1: per-source-type field extractors |
| `src/solstein/research/signals.py` | Layer 2: `_SIGNAL_EXTRACTORS` (only 10 defined) |
| `src/solstein/research/company_builder.py` | Layer 3: `build_company_entity_from_signals()` |
| `src/solstein/domain/models.py` | Layer 4: `extra="ignore"` silences all errors |

## ADDENDUM 2: Deep Gap Analysis — Remaining Blockers to Production (2026-04-03)

> Added after systematic code review of auth, agents, health checks, multi-tenancy, Celery, and scoring.
> New EPICs: EPIC-087 (multi-tenancy), EPIC-088 (infra reliability), EPIC-089 (workflow API).
> New stories: STORY-352–364 added to `planning/QUEUE.md`.

### What the Prior Audit Got Wrong

| Prior Claim | Actual State |
|-------------|-------------|
| "Auth accepts any credentials" | **Incorrect** — Supabase Auth SDK handles JWT auth correctly. The gap is API key validation (stub) and MFA (stub), not the primary auth path. |
| "7+ stub agents returning None" | **Incorrect** — GitHub, WebSearch, Website, and CompaniesHouse agents are fully implemented. The gap was in the data pipeline transformation layers, not the agents. |
| "Health checks are asyncio.sleep + return True" | **Partially correct** — DB, Redis, LLM, and disk checks are real. Only the Celery check is a placeholder. |

### Confirmed Remaining Gaps (2026-04-03)

#### 1. Multi-Tenancy Not Enforced (EPIC-087 — P1)

The infrastructure exists (migrations, models, middleware) but is not wired:
- `TenantIsolationMiddleware` defined but NOT registered in `src/solstein/api/main.py`
- RLS policies may not be deployed in PostgreSQL (referenced in a Supabase migration file not in Alembic)
- `_validate_api_key()` returns `None` unconditionally — any API key accepted

**Risk**: Cross-tenant data leakage is possible today.

#### 2. Celery Health Check Placeholder (EPIC-088 — P2)

`check_celery()` in `monitoring/health.py` returns hardcoded `{"status": "healthy", "workers": 0}`.
A complete broker outage looks healthy. No startup check verifies Redis reachability.
Beat schedule has 12 tasks with no test that they are importable.

#### 3. No Workflow API (EPIC-089 — P1)

`GET /jobs/{workflow_id}` returns HTTP 501. The system cannot be used as an async API product — clients submit work but cannot track or retrieve results. The `ResearchRunRecord` + `ResearchStageRecord` tables already capture the right state; they just need an API surface.

#### 4. No Unit Tests for Two Critical Pipeline Layers (EPIC-086 — P0)

`aggregate.py` extractors and `signals.py` extractors have zero isolated unit tests. These are the layers where 70%+ of data was lost. STORY-355 and STORY-356 add the missing test coverage.

#### 5. Classification Threshold Maintenance Trap (EPIC-003 — P3)

Thresholds are currently consistent across 3 files but there is no guard preventing future divergence. STORY-360 consolidates them; STORY-361 adds a regression test.
