## ⛔ MANDATORY FIRST READ — Every Session, No Exceptions

**Before writing a single line of code, before reading any epic, before running any command:**

```
Read: backlog/EXECUTION_ORDER.md
```

This file is the **only** authority for what to work on. It contains a numbered queue of 95 stories
ordered by dependency and priority. Your job is simple:

1. Open `backlog/EXECUTION_ORDER.md`
2. Find the **first row whose Status = READY** in the current phase
3. Read the linked story file
4. Run the Before-grep from the story to confirm the bug exists
5. Implement, test, mark DONE in the queue file, commit

**That is the complete decision procedure.** There is no other valid way to pick a story.

## Story Selection Rules (Hard Constraints)

| Rule | What it means |
|------|--------------|
| **Only work stories in the queue** | Do not invent stories, do not pull from GitHub issues, do not pick from epic READMEs directly |
| **Top-to-bottom only** | Never skip ahead to a lower-numbered row while higher rows are READY |
| **Never self-unblock** | If a row says BLOCKED, it stays BLOCKED until the story it depends on is DONE — do not bypass |
| **Never cross a gate** | Gate criteria are listed at the bottom of each phase. If the gate is not satisfied, stop and report |
| **One story per session** | Finish what you start. Do not begin a second story if the first is incomplete |
| **No bulk status changes** | Do not mark multiple stories DONE in one commit without doing the work for each one |

## Prohibited Actions

- **Do not change `extra="ignore"` back to silence errors** — `extra="forbid"` is intentional on `Company` and `FinancialMetric`

- **Do not add `app.dependency_overrides` at module scope** in any test file
- **Do not set `os.environ["DATABASE_URL"]` at module scope** in any test file
- **Do not delete `src/solstein/cli_research.py`** — it is an active caller
- **Do not delete `src/solstein/api/routers/review.py`** — it is an active caller
- **Do not delete `research/graph/`** without team sign-off (see STORY-343)
- **Do not mark a story DONE without running tests** — green tests are required before every commit
- **Do not amend published commits** — always create a new commit

## Implementation Protocol

Every change follows: **MEASURE → CHANGE → TEST → MEASURE → KEEP/DISCARD**

1. Run the Before-grep from the story file — confirm the problem exists exactly as described
2. Make the change
3. `PYTHONPATH=src .venv/bin/python3 -m pytest tests/unit/ -x -q --no-header 2>&1 | tail -5`
4. If red: revert and try a different approach — do not push broken tests
5. If green: run the After-grep from the story file — confirm the fix is in place
6. Commit with `feat(STORY-NNN): <title>` + update `backlog/EXECUTION_ORDER.md` Status in the same commit
