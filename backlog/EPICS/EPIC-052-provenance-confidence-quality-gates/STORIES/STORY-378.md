# STORY-378: Fix `src/solstein/data/seed_db.py` — set `data_source_type` before `repo.save()`

## Context

`src/solstein/data/seed_db.py` is a **production module** (inside `src/`, not `scripts/`).
It loads companies from `competitor_data.json` via `CompetitorDataLoader`, scores them, and
saves to Supabase — all without setting `data_source_type`. Records land with the default
`"unknown"` which passes the export gate.

```python
async def seed_supabase() -> None:
    loader = CompetitorDataLoader()
    repo = SupabaseRepository()
    scorer = GrowthScorer()
    companies = loader.load_companies()
    for company in companies:
        scored_company = scorer.calculate_scores(company)
        repo.save(scored_company)   # ← data_source_type never set
```

This is distinct from `scripts/seed_db.py` which uses Faker — this module seeds from JSON.
The loaded data may be synthetic (if `competitor_data.json` was generated by
`scripts/generate_synthetic_companies.py`) or real. This story tags it correctly.

## Acceptance Criteria

- [ ] Before `repo.save(scored_company)`, `scored_company.data_source_type` is set to a

- [ ] Minimum viable fix: check if `company.data_source_type == "unknown"` and set it to
      `"real"` if the loader's source file is `data/input/competitor_data.json`
      (the production source — contrast with `tests/fixtures/synthetic/`)
- [ ] Add a module-level docstring note explaining what `data/input/competitor_data.json`
      is expected to contain (real vs. synthetic)

## Technical Notes

**Read first**: Confirm `Company` domain model has a mutable `data_source_type` field
(it does — `domain/models.py:294`). The scored_company returned by `GrowthScorer` is still
a `Company` object.

**Simplest correct fix**:
```python
for company in companies:
    if company.data_source_type == "unknown":
        company.data_source_type = "real"   # this file is production competitor data
    scored_company = scorer.calculate_scores(company)
    repo.save(scored_company)
```

**Better fix**: parameterize the source type via the function signature so callers can
override if needed — but only if that doesn't require more than 10 additional lines.
Don't over-engineer: this is an XS story.
